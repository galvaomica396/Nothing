# 비식별 정책 (De-identification Policy)

`privacy_transformers.py`는 탐지된 개인정보 토큰(`[NAME]`, `[PHONE]` 등)을 세 가지
정책 중 하나로 치환한다. 정책마다 **노출 수준(residual disclosure)** 이 다르므로,
공문의 활용 목적과 준식별자(quasi-identifier) 결합 위험을 함께 고려해 선택해야 한다.

이 문서는 각 정책이 실제로 얼마나 남기는지를 명시한다. 로직 자체는
`privacy_transformers.py`의 함수 docstring과 1:1로 대응한다.

## 정책 요약

| 정책 | 설명 | 재식별 위험 | 권장 용도 |
|------|------|-------------|-----------|
| `token` (기본) | 값을 `[TAG]`로 완전 치환. 원본 정보 0% 노출 | 가장 낮음 | 외부 공개·배포, 최고 수준 보호가 필요할 때 |
| `partial` | 값의 일부(뒷자리·성씨·시도 등)를 남겨 가독성 유지 | **중간~높음** | 내부 검토용. 문서 흐름 파악이 필요하되 원문 노출은 피할 때 |
| `pseudonym` | 값을 일관된 가짜 값으로 치환(동일 원본→동일 가명) | 낮음(단, 연결성 유지) | 통계·연결 분석이 필요하되 실명은 감춰야 할 때 |

`token`이 기본값이며, 알 수 없는/미지정 정책 문자열은 모두 `token`으로 안전하게
정규화된다(`normalize_deidentification_policy`).

## 제품 적용 범위

마스킹 설정의 `비식별 TXT 함께 저장`을 켰을 때만 정책 선택이 활성화되며,
엔진에는 `pdf_masked_txt_safe_report` 산출물 모드로 전달된다. 세 정책은 동일한
탐지 결과에 변환만 달리 적용하므로 탐지 건수는 줄어들지 않아야 한다. 원문 추출
TXT는 최종 저장 대상이 아니며, 호환용 `extractedPath` IPC 필드에 값이 들어와도
Rust 저장 계층이 게시하지 않는다. 정책을 변경한 뒤에는 다시 실행해야 새 정책의
비식별 TXT가 저장된다. PDF 표시 방식은 이 선택과 독립적이다.

## 검증 정책과 마스킹의 분리 (v4.2.0)

비식별(마스킹) 변환 자체와 "저장 게이트"는 별개 계층이다. v4.2.0에서 저장 게이트가
하드 차단에서 권고형으로 바뀌었지만(**검증은 항상 수행·기록되고 결과는 권고로
표시되며, 최종 저장은 사용자의 명시적 확정 "그대로 저장"으로 항상 가능하다**),
**이 문서가 규정하는 마스킹/비식별 변환 자체는 조금도 축소되지 않는다.** 각 정책의
노출 수준(`token` 0% · `partial` 부분 · `pseudonym` 일관 가명)과 폴백 규칙은
불변이며, 저장 권고형 전환과 무관하게 그대로 적용된다.

## `partial` 정책이 노출하는 값 (중요)

`partial`은 **의도적으로 원본의 일부를 남긴다.** 아래 항목은 그대로 노출되므로,
준식별자 결합 시 재식별 위험이 있다.

| 태그 | 치환 결과 예시 | 남는 정보 |
|------|----------------|-----------|
| `PHONE` | `010-****-1234` | 통신사/지역 **앞 3자리 + 뒤 4자리** |
| `EMAIL` | `h***@example.com` | 로컬 파트 **첫 글자 + 전체 도메인** |
| `NAME`, `LEGAL_PARTY`, `APPROVAL_LINE`, `ATTORNEY` | `홍OO` | **성씨(첫 글자)** |
| `ADDRESS`, `REGION` | `서울특별시 [ADDRESS_DETAIL]` | **시·도(광역 행정구역)까지** |
| `BUSINESS_REG_NO` | `***-**-56789` | 사업자번호 **뒤 5자리** |
| `CARD` | `****-****-****-1234` | 카드번호 **뒤 4자리** |
| `COMPANY`, `LAW_FIRM`, `COURT` | `한**` | 기관명 **첫 글자** |

전화 뒤 4자리·성씨·시도 등은 개별적으로는 식별력이 약해 보여도,
**여러 준식별자가 결합되면 특정 개인으로 좁혀질 수 있다.** 예를 들어
`성씨 + 시도 + 전화 뒤 4자리 + 사업자번호 뒤 5자리`의 조합은 소규모 모집단에서
사실상 유일 식별자로 작동할 수 있다.

값의 길이가 최소 요건에 못 미치면(예: 전화 자릿수 부족, 도메인 없는 이메일)
`partial`은 부분 노출을 포기하고 `[TAG]` 전체 마스킹으로 안전하게 폴백한다.

## 준식별자(Quasi-identifier) 위험

준식별자는 단독으로는 식별자가 아니지만, 외부 정보나 다른 준식별자와 결합하면
개인을 특정할 수 있는 속성이다(성별, 생년, 시·도, 직역, 성씨 등).

- `partial` 정책은 성씨·시도·전화 뒷자리 같은 **준식별자를 그대로 남기므로**,
  결합 공격(linkage attack)에 취약하다.
- `pseudonym` 정책은 원본을 감추지만 **동일 원본을 동일 가명으로 매핑**하므로
  (연결성 보존), 같은 인물의 등장 빈도·패턴은 유지된다. 빈도 기반 추론에 주의.
- 외부 공개·재배포 시에는 준식별자 노출이 없는 `token` 정책을 기본으로 사용할 것.

## 구현 참고

- 정책 적용 진입점: `apply_deidentification_policy(masked_text, matches, policy)`.
  이미 `[TAG]`로 마스킹된 텍스트를 받아, 탐지 순서대로 토큰을 정책값으로 치환한다.
- `pseudonym`의 가명은 `sha256(tag\0value)` 기반의 **결정론적** 매핑이라
  같은 실행/다른 실행에서 동일 원본은 항상 같은 가명을 받는다(가명 풀 고정).
- 이 문서의 노출 수준은 `partial_value` / `pseudonym_value` 함수와 일치해야 한다.
  둘 중 하나를 변경하면 이 표도 함께 갱신한다.
